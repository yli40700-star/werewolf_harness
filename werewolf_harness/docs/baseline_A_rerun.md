## 怎么测的

- **成本**：每局 `usage`：`gateway_*` 为 CLI JSON 报告（input + cache 读 + cache 写 + output），`prompt/completion_tokens` 为发送前的本地估算（预算上限用它）。调用数 = 每回合非兜底 ReAct 步 + 1 次笔记（有 note_ms 或回合耗时大于步耗时之和）；与 usage.calls 逐局核对。
- **延迟**：单次调用 = react_trace[].latency_ms；回合墙钟 = timings 的 committed − asked；阶段 = journal 中同一任务的连续段，阶段墙钟 = 本段最后一次提交 − 上一段最后一次提交（即该阶段占用的游戏时钟）。
- **可靠性**：以 ReAct 步为单位看 `guard_blocked/block_reason`（schema 含畸形输出与非白名单工具；semantics 为参数/状态校验；say_do_consistency、directive_compliance、evidence 为 L3/L2 守卫）；以回合为单位看 `recovery`。
- **言行一致**：保守正则抽取三档声明（明确投票意向 > 点名怀疑 > 保人/不投），拒读过去时（投了/第一天/昨天/当时…）、条件句（如果/假如/是不是…）、转述（验/报/自称/起跳…），自相矛盾的座位丢弃，两个不同明确意向整篇不读；对比同轮引擎记录的票（abstain 记为不一致）。
- **预言家诚实**：只读自称预言家者的第一人称验人（“首夜查验了2号，结果是好人”，前面没有别的主语），裁决为同句内第一个好/狼词；与 night 日志中该真预言家的 night_check 结果比对（未验过却报 = 编造）。
- **泄露**：抽取确定语气、无对冲、非转述的“N号是X”；依据分三类：私有（狼队友 / 预言家自己验过 / 女巫看到被刀）、公开（此前任何发言在同一子句里把 N号 与同类词放在一起，或 N号自报该身份，或夜里被刀之于“好人”——故意放宽，只会减少泄露标记）、无依据。无依据断言的正确率若显著高于随机基线，才是泄露信号。复盘阶段（身份已公开）不计。另做两项不依赖文本的结构检验：首夜狼刀（多数狼的提议）命中预言家的比例 vs 1/6；首日当天无自称预言家报查杀的局里，村民/女巫的票落在狼上的比例 vs 可投座位中狼的占比。
- **CI**：比例 Wilson；“簇”与所有均值/分位数 = 按局有放回重抽样 2000 次的百分位区间（种子 0）。
- **复现**：`python -m werewolf_harness.scripts.eval_baseline 'runs/base/g*.json' --compare '顺序(pilot)=runs/pilot/g*.json' --compare '并行(fast)=runs/fast/g*.json' --out docs/baseline_A.md --json docs/baseline_A.json`；新模型/新板子跑完 `cli play --out` 后同一条命令即可出同格式报告。

## 注意事项

- 只有 haiku 一个模型、只有 8 人局（2 狼 / 预言家 / 女巫 / 4 民）、只有静态 playbook 与 L1+L2+L3 守卫；结论不外推到其它模型或板子。
- 言行一致的覆盖率很低（任一档 6.7%）：haiku 的发言多数是“先听发言再决定”，一致率只描述那一小部分有明确表态的发言；而且发言后才轮到别人发言，改票可能是合理的。
- 最终票已经被 L3 say_do 守卫“推”过（被拦后重提），因此最终票一致率偏高；第一次提出的票更接近模型本身。反过来，守卫的正则会把“验出N号”读成“出N号”=投票意向，详见 5.1 审计。
- 正则抽取有漏读与误读；每类都在 JSON 里留了样例（`inconsistent_examples`、`leak_candidates`、`fake_examples`、`guard_audit.examples`）供人工抽查。
- 对比组 pilot / fast 各只有 2 局，且顺序版与并行版的对局轨迹不同（同种子，模型输出不同），只能当方向性证据。
