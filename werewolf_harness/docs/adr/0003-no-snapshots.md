# ADR 0003：不做快照，只做重放

- 状态：已采纳（先量再决定）

计划里原本写了「每 20 步存一份快照」。实现之前先量了一下：

- 一整局 12 人局（mock 模型，88 步）从种子加 journal 重放：**约 2.5 ms**；
- 节点接管一局的全过程（抢租约、bump fencing、读 journal、重放、恢复模型记忆、拉起 actor）：30 步时 **p50 9.5 ms / p95 13.9 ms**，整局长度（中位 89 步）时 **p50 13.4 ms / p95 19.8 ms**（20 次采样，`scripts/bench_runtime.py`）。

恢复耗时的大头是租约 TTL（默认 10 s）加扫描间隔，重放本身可以忽略。快照带来的代价是：状态要可序列化、格式要版本化、快照和 journal 可能不一致。收益为零，所以不做。

什么时候需要快照：单局 journal 到几万步（比如长期运行的沙盒世界），或者引擎的单步变得很重。届时在 `agent_state` 旁边加一张 `snapshots(game_id, seq, state, schema_version)` 表，恢复改为「最近快照 + 之后的 journal」。
